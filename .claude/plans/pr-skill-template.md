# Шаблон описания PR для skill `pr`

## Context

По документации Claude Code по skills, в директории скилла рядом с `SKILL.md` можно держать вспомогательные файлы, в том числе `template.md`: шаблон, который Claude заполняет. Это не обязательно, но считается хорошей практикой. Сейчас у `/pr` шаблон описания PR (`## Summary` / `## Почему` / `## Test plan`) встроен прямо в шаг 5 `SKILL.md`. Если вынести его в отдельный файл, формат будет в одном месте, а `SKILL.md` станет короче. Это продолжает разбор скилла на части: `scripts/validate.sh` уже вынесен.

## Подход

1. **Создать `.claude/skills/pr/template.md`** (имя и расположение — как в примере из документации) с телом PR:
   - `## Summary`: 1–3 пункта о том, что изменено;
   - `## Почему`: контекст, только если он не очевиден из Summary;
   - `## Test plan`: `- [x] npm run typecheck, npm run lint, npm run build проходят` и `- [ ] <как проверить само изменение>`.
   Заполнители — в `<…>`. Правила заполнения (`[x]` только у реально проверенного, «Почему» можно пропустить) коротко пишутся HTML-комментариями `<!-- … -->` над секциями. Модель удаляет их перед отправкой; если какой-то останется, GitHub его не отобразит.

2. **Обновить шаг 5 в `.claude/skills/pr/SKILL.md`**: вместо встроенного блока ```markdown написать «Описание составь по [template.md](template.md): заполни все `<…>`, удали комментарии». Правило про `[x]` оставить в `SKILL.md` одной строкой, потому что это правило поведения, а не формат.

3. **Шаг 6** почти не меняется. В heredoc `PR_BODY_EOF` передаётся заполненный шаблон, без `<…>` и `<!-- -->`. Добавить в пост-проверку: в теле не должно остаться незаполненных `<…>`.

4. **Сохранить план в проекте**: скопировать его в `.claude/plans/pr-skill-template.md` с чеклистом (как принято в репо).

`allowed-tools` не меняется: файлы скилла читаются через Read, для этого `allowed-tools` не нужен.

## Чеклист

- [x] Сохранить план в `.claude/plans/pr-skill-template.md`
- [x] Создать `.claude/skills/pr/template.md`
- [x] Заменить встроенный шаблон в шаге 5 `SKILL.md` ссылкой на `template.md`
- [x] Шаг 6: проверка, что в теле PR не осталось `<…>`

## Критичные файлы

- `.claude/skills/pr/SKILL.md`: шаги 5 и 6
- `.claude/skills/pr/template.md`: новый файл

## Проверка

- `git diff` по `SKILL.md`: в шаге 5 больше нет встроенного markdown-шаблона, есть ссылка на `template.md`, а секции в шаблоне совпадают с прежними.
- Прочитать `template.md` глазами: заголовки секций совпадают с описанием в `CLAUDE.md` (`## Summary` / `## Почему` / `## Test plan`).
- Сухой прогон: по текущей ветке заполнить шаблон вручную (без `gh pr create`) и убедиться, что получается корректное тело PR.
