# План: редизайн frontend по референсу (Wallet dashboard)

> Выполняем по одному пункту чеклиста за раз, с подтверждением перед следующим.
> Ветка: `feat/frontend-redesign` от актуального `origin/master`. Коммиты — через `/commit`.

## Context

Сейчас приложение тёмное (`--surface-0…4`, голубой `--brand`, системный шрифт, `rounded-md`-карточки с `ring-1`). Референс — светлый: серый холст, крупные скруглённые панели, пастельные плитки (мятная / сиренево-голубая / персиковая), почти чёрные «чернильные» карточки, геометрический гротеск, много воздуха.

Меняется **только визуальный слой**. Данные, роуты, FSD-границы, API не трогаем. Из референса не переносим то, чего в приложении нет (поиск, уведомления, график, крипто-таблица).

Главное решение: **тема становится светлой**. Тёмная тема исчезает (переключателя не было, она была единственной), правки в `CLAUDE.md` и `.claude/docs` обязательны (пункт 9).

## Дизайн-план

### Цвет (4–6 базовых значений, остальное — производные)

| Токен | Hex | Роль |
|---|---|---|
| `--canvas` | `#EFEFF2` | фон страницы и сайдбара |
| `--paper` | `#FAFAFB` | основная панель контента, карточки, диалоги |
| `--ink` | `#15121F` | тёмные карточки, основная кнопка, текст |
| `--mint` / `--periwinkle` / `--peach` | `#E3F6E5` / `#E5E9F8` / `#FBE7DD` | пастельные заливки: доход, нейтральное, расход |
| `--ink-muted` | `#666672` | вторичный текст (≥4.9:1 на canvas и paper) |

Отличия от референса, сделанные осознанно: серый текст референса (≈`#9A9AA3`) не проходит WCAG AA (≈3:1), поэтому вторичный текст темнее. Доход — `#187A41` (читаем на светлом), расход — обычный ink со знаком «−». Границы почти не используем: разделение тоном заливки, а не рамками и тенями.

### Типографика

Один шрифт — **Onest** (Google Fonts, есть кириллица; приложение русскоязычное, Gilroy-подобный геометрический характер референса). Подключение через `next/font/google` (`subsets: ['cyrillic', 'latin']`, `variable: '--font-sans'`).

- Заголовок страницы: 28/1.15, 700, `-0.02em`
- Заголовок секции: 18/1.3, 700
- Основной текст: 14/1.5, 400 / 500
- Вторичный: 13/1.45, 400, `--muted`
- Суммы: 500–700, `tabular-nums`
- Без ALL-CAPS-меток, без «эйбрау» над заголовками.

### Форма и раскладка

- Радиусы по иерархии, а не один на всё: 32px — панель контента и тёмная карточка в сайдбаре; 24px — диалоги, карточки; 999px — кнопки, поля, чипы, пилюли меню.
- Каркас: канвас → слева прозрачный сайдбар (`Sidebar variant="inset"` уже умеет «вложенную» панель), справа белая панель со скруглением 32px.
- Шапка-полоса с `border-b` уходит. Заголовок страницы — крупный H1 внутри панели, справа основное действие. `SidebarTrigger` остаётся только на мобильных.
- Выравнивание: всё по левому краю, суммы и даты — по правому.

```
┌ canvas ─────────────────────────────────────────────┐
│  Трекер          ┌ paper (r=32) ─────────────────┐  │
│                  │ Главная          [+ Добавить] │  │
│  ◔ Главная  (●)  │                               │  │
│  ⇄ Транзакции    │ Последние транзакции          │  │
│  ◇ Категории     │ (↘) Продукты      −1 240 ₽    │  │
│                  │ (↗) Зарплата    +85 000 ₽     │  │
│  ┌ ink (r=32) ┐  │ …                             │  │
│  │ Имя        │  │              ‹ 1 из 4 ›       │  │
│  │ mail       │  └───────────────────────────────┘  │
│  └────────────┘                                     │
└─────────────────────────────────────────────────────┘
```

### Что становится «запоминающимся элементом»

Одна тёмная (`--ink`) карточка профиля внизу сайдбара, как «History available» в референсе. Всё остальное спокойное: светлые тона, пастель только в семантических местах (иконки направления транзакций).

### Проверка плана против «дефолтов»

- Крем + терракота, чёрный + кислотный акцент, газетная сетка — не используем; палитра прямо из брифа.
- «SaaS-карточки одинакового радиуса с одинаковой тенью» — избегаем: радиусы разные по иерархии, вместо теней тональные заливки.
- Пришлось поправить сам референс: контраст вторичного текста (см. выше).

## Открытые вопросы

1. **Пастельные плитки со статистикой** (доходы / расходы / баланс, как три верхние карточки референса). Данных для них нет: `GET /transactions` пагинирован, сводки нет, а считать по текущей странице — вводить в заблуждение. Рекомендация: **не делать в этой ветке**, отдельной задачей с эндпоинтом `GET /transactions/summary`. Если нужны сразу — добавляем backend в план.
2. **Незакоммиченный `.claude/settings.json`** (включён плагин `frontend-design`, переставлен порядок ключей) лежит в рабочей копии на ветке `chore/claude-commit-dynamic-context`. При `git switch -c` он уедет в новую ветку. Предлагаю не смешивать с редизайном: закоммитить/отложить отдельно до старта.
