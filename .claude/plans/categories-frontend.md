# План: добавление категорий (frontend)

> Выполняем по одному пункту чеклиста за раз, с подтверждением перед следующим.
> Ветка: `feat/frontend-create-category` от актуального `origin/master`. Коммиты — через `/commit`.
> Backend-часть категорий описана в [`categories.md`](categories.md), здесь только frontend.

## Context

Backend уже умеет `POST /categories` (`name` ≤ 50, `color` — HEX, `icon` — строка ≤ 50), но в UI категорий нет. `/categories` — заглушка `SectionPlaceholder`, а без категории транзакцию не сохранить. Сейчас новый пользователь создаёт первые категории через Swagger (`developer-guide.md`, «Первый вход»).

Задача: на странице `/categories` показать категории пользователя и дать создать новую в диалоге, по образцу создания транзакции (`features/transaction/create`).

## Решения

1. **Скоуп: создание и просмотр.** Редактирование и удаление (`PATCH`/`DELETE /categories/:id`, 409 при удалении категории с транзакциями) — отдельная задача. Backend не меняется.
2. **Цвет выбирается из готовой палитры**, произвольного HEX нет: пользовательский цвет на светлом фоне часто нечитаем (жёлтый, светло-зелёный). Все 8 цветов проверены: и кружок-образец, и иконка на светлой подложке своего цвета дают контраст ≥ 3:1 (WCAG 1.4.11 для графики).

   | Цвет | HEX | Контраст на `--paper` | Иконка на подложке 16% |
   |---|---|---|---|
   | Красный | `#E03131` | 4.33 | 3.43 |
   | Оранжевый | `#D9480F` | 4.12 | 3.34 |
   | Янтарный | `#B45309` | 4.81 | 3.87 |
   | Зелёный | `#2B8A3E` | 4.19 | 3.44 |
   | Бирюзовый | `#0C8599` | 4.17 | 3.40 |
   | Синий | `#1971C2` | 4.81 | 3.88 |
   | Фиолетовый | `#7048E8` | 5.32 | 4.26 |
   | Розовый | `#D6336C` | 4.43 | 3.52 |

   Категории, созданные раньше через API с другим цветом, отображаются с ним без изменений.
3. **Иконка выбирается из отобранного набора lucide.** Backend хранит имя в kebab-case (`shopping-cart`), фронт сопоставляет его с компонентом через реестр «имя → компонент». В наборе около 24 иконок: продукты, кафе, жильё, транспорт, здоровье, зарплата, сбережения, «другое» и т.д. Имя не из реестра (например, созданное через Swagger) показывается иконкой `tag`. `DynamicIcon` из `lucide-react/dynamic` не подходит: он загружает каждую иконку отдельным чанком при первом показе и добавляет в бандл карту имён всех иконок lucide.
4. **Как выглядит категория.** Круг со светлой подложкой цвета категории (`color-mix(in srgb, <color> 16%, transparent)`) и иконкой того же цвета, по аналогии с пастельными кругами направления у транзакций. Строка транзакции не меняется: там по-прежнему точка цвета категории.
5. **Цвет и иконка выбираются через нативные `<input type="radio">`**: визуально скрыты внутри `<label>` и подключены через `register()`. Стрелки, Tab и скринридеры работают без дополнительного кода, `RadioGroup` из shadcn не нужен.
6. **Значения по умолчанию.** Иконка `tag`. Цвет — первый в палитре, которого ещё нет у категорий пользователя; если заняты все, берётся первый. Можно просто ввести название и нажать Enter.

## Детали

- **Схема** повторяет `CreateCategoryDto`:
  - `name`: `trim()`, «Введите название», не длиннее 50 символов. Trim обязателен: строку из пробелов backend сохранил бы (`api.md`, «Известные ограничения»);
  - `color`: `#RRGGBB`;
  - `icon`: непустая строка.
- **`useCreateCategory`** вызывает `invalidateQueries({ queryKey: categoryKeys.all })`. Так обновятся и список на `/categories`, и `Select` в форме транзакции.
- **Форма** устроена как `CreateTransactionForm`:
  - `rootError` через `getApiErrorMessage`;
  - синхронный `ref`-флаг против двойной отправки;
  - «Сохраняем…» на кнопке, пока идёт запрос;
  - футер через `renderFooter`, форма не зависит от `Dialog`.
- **Сетки выбора** в 8 колонок: палитра занимает один ряд, иконки — три.
  - У каждого варианта есть русская подпись для скринридера (`aria-label` на radio, у иконок ещё и `title`) и видимый фокус с клавиатуры (обводка `--ink`).
  - Выбор отмечен не только цветом: у цвета — кольцо и галочка, у иконки — кольцо и подложка выбранного цвета.
  - Выбранная иконка рисуется в выбранном цвете, поэтому отдельное превью не нужно.
- **Список** (`CategoriesList`) берёт данные из `useCategories()`. Backend сортирует по дате создания, поэтому новая категория появляется в конце.
  - Состояния: скелетон; ошибка с кнопкой «Повторить»; пустой список — «Категорий пока нет — добавьте первую».
  - Шапка как у `TransactionsList`: подзаголовок `h2` (не повторяет `h1` «Категории» из `AppShell`), «Всего: N», справа кнопка «Добавить».

## Вне скоупа

- Редактирование и удаление категорий, методы `patch`/`delete` в `apiClient`.
- Иконки категорий в строке транзакции и в `Select` формы транзакции.
- Уникальность названий (backend её не проверяет).

## Проверка

1. `docker-compose up postgres -d`, затем `npm run dev` из корня. Войти новым пользователем.
2. `/categories`: пустое состояние → «Добавить» → ввести «Продукты», выбрать цвет и иконку. Ожидается: диалог закрылся, категория появилась в списке, «Всего: 1».
3. Валидация: пустое название, строка из пробелов, 51 символ. Ожидается: ошибка под полем, запрос не уходит (вкладка Network).
4. Ошибка сервера (остановить backend). Ожидается: текст ошибки в форме, диалог открыт, введённые данные на месте.
5. Двойной Enter или двойной клик по «Добавить» создаёт одну категорию.
6. Клавиатура: Tab по полям, стрелки внутри палитры и сетки иконок, Enter отправляет форму, Esc закрывает диалог. Фокус везде виден.
7. Цвет по умолчанию: вторая категория получает следующий свободный цвет палитры.
8. Главная → «Добавить» транзакцию: новая категория есть в `Select`. У пользователя без категорий ссылка «создайте категорию» ведёт на `/categories`.
9. Категория с иконкой не из реестра (создать через Swagger с `icon: "unknown"`) показывается иконкой `tag`.
10. На 390px диалог и сетки помещаются без горизонтальной прокрутки, области нажатия не меньше 24px.

## Результат проверки

- `npm run typecheck`, `npm run lint`, `npm run build` из корня проходят.
- Сценарии 2–10 прогнаны e2e-скриптом на production-сборке: `playwright-core` + установленный Google Chrome в headless-режиме, отдельный временный профиль, свежий тестовый пользователь. Результат: 21/21 на 1440px и 21/21 на 390px. Ошибку сервера проверял подменой ответа `POST /categories` на 500, а не остановкой backend.
- Дополнительно проверено: ошибка загрузки списка и кнопка «Повторить», длинное название на 390px.
- **Найдено и исправлено:** на 390px длинное название вылезало за край панели без многоточия. У `ul` с `grid` не было явных колонок, и неявный `auto`-трек растягивался под текст с `nowrap`. Исправлено через `grid-cols-1` (`minmax(0, 1fr)`). Проверка «нет горизонтальной прокрутки» этого не ловила: у `html, body` в `globals.css` стоит `overflow-x: hidden`.
- Не относится к задаче: 404 на `/favicon.ico` (в проекте нет favicon).
